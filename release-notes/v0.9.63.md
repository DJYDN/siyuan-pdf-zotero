# SiYuan PDF × Zotero v0.9.63

## 本版修复：OCR 首次/后续识别慢

根本原因：

- 引擎服务 `/health` 会触发模型加载，插件在等待启动时每 600ms 轮询一次，Pix2Text 又没有初始化锁，导致同一模型被并发加载多次；
- 插件健康检查 4 秒超时就重新启动服务，且没有单飞锁，会生成两个同端口进程（实测 8891 上曾有两个 Pix2Text）；
- 多引擎 fallback 会在识别途中冷启动下一个引擎，每次识别叠加 1–3 分钟模型加载。

修复：

- **启动预热**：插件启动后后台预热公式首选引擎（Texo）与文本首选引擎（Pix2Text），默认开启，可在设置关闭；
- **单实例**：引擎服务 `allow_reuse_address = False`，同端口不会再启动第二个进程；
- **/health 不再加载模型**，只返回 `ready / loading / error`；新增 `/warmup` 显式加载，并给 Pix2Text/UniMERNet 的 `init_engine` 加锁；
- **插件单飞启动**：同一引擎的并发识别/预热/检测共享一次启动，等待轮询改为 2 秒；
- **回退策略**：首选引擎允许启动/预热；备用引擎只在已就绪时回退，不再自动冷启动；
- **大图降采样**：截图长边超过 2200px 时先等比缩小再 OCR（设置可调 1600/2200/3000/不限制）；
- 服务启动/预热失败时直接返回具体错误，便于定位。

实测（本机副本，独立端口）：

| 项目 | 结果 |
|---|---|
| Texo `/health` | 约 2.1s（服务监听后立即返回，不加载模型） |
| Texo `/warmup` | 约 6.5s |
| Pix2Text `/health` | 约 2.7s（不加载模型） |
| Pix2Text `/warmup` | 约 110s（只加载一次） |
| 同端口第二实例 | 启动失败退出，原进程 PID 不变 |
| 旧 OCR-Service `/health` | 约 0.5s |

- 插件：安装 `siyuan-pdf-zotero-0.9.63.zip` 覆盖旧版；
- 便携包：解压 `-0.9.63` 新包，在设置里选择对应目录；已运行的旧服务建议先停止再切换；
- 首次启动会后台预热，可能需要 1–2 分钟（Pix2Text/UniMERNet），之后识别不再重复加载。
